## 0. レンダリング階層（必ず最初に読む）

このゲームは **4つのレンダリング階層** でオブジェクトを管理します。  
同じ「カントリーマアムの袋」でも、「ゲームで変化するオブジェクト」か「背景の飾り」かで **別の階層** に入ります。

```
階層1 MergedBackground  ── エリアごとにBlenderでJoin → 1〜5 DrawCall
階層2 Instanced         ── 同一メッシュ×N個 → 1 DrawCall per 種類
階層3 AnimLoop          ── before/after変化するゲームオブジェクト → 1 DrawCall per 個
階層4 Rigged            ── ボーンアニメあり (主人公・NPC人物) → 1 DrawCall per 個
```

### DrawCall の目安（街1エリア）

| 階層 | 典型例 | DrawCall |
|------|--------|----------|
| MergedBackground | 道路・建物・歩道・信号・ベンチ一式 | 1〜5 |
| Instanced | ゴミ箱×10、ポスター×15、自販機×5 | 3（種類数） |
| AnimLoop | 看板・カントリーマアム・制服丈 等 | 個数分（数十〜） |
| Rigged | ゆかり・モブNPC×N | 個数分 |

> **悪い例（旧設計）:** 看板・ゴミ箱・お菓子すべてを個別GLBにすると  
> オブジェクト80個 × メッシュ4 = **320 DrawCall** になる。  
> 上の設計なら同じ街が **〜30 DrawCall** で収まる。

## 1. どの階層を選ぶか（フローチャート）

```
そのオブジェクト、ゲームで "before/after" が切り替わる？
├── YES → 【階層3 AnimLoop】
└── NO
    ├── キャラクターでボーンアニメがある？
    │   ├── YES → 【階層4 Rigged】
    │   └── NO
    │       ├── 同じ形のモデルが複数個ある？ (ゴミ箱、ポスター等)
    │       │   ├── YES → 【階層2 Instanced】
    │       │   └── NO（一意の建物・地面・ベンチ等）
    │       │       └── 【階層1 MergedBackground】にJoinして組み込む
```

### 具体例

| オブジェクト | 説明 | 階層 |
|------------|------|------|
| 道路・歩道・信号・外壁 | 動かない、一意、背景 | **1 MergedBackground** |
| ゴミ箱×10 | 動かない、同一形状の繰り返し | **2 Instanced** |
| 自販機×5（全部同じモデル） | 動かない、同一形状 | **2 Instanced** |
| カントリーマアムの袋（ゲームオブジェクト） | before/after で大きさが変わる | **3 AnimLoop** |
| 歯科医院の看板 | before/after で顔が変わる | **3 AnimLoop** |
| ゆかり（主人公） | ボーンアニメあり | **4 Rigged** |
| モブNPC（頂点アニメ） | モーフターゲットで歩行を表現 | **4 Rigged** ※後述 |

## 3. Blenderからのエクスポート設定

### 共通設定（全階層）

| 項目 | 設定値 |
|------|--------|
| フォーマット | **GLB**（単体バイナリ、テクスチャ埋め込み） |
| Y-up変換 | **ON** |
| テクスチャ | GLB内に**埋め込む** |
| スケール適用 | **Ctrl+A → Apply Scale** |
| マテリアル | **Principled BSDF** を使うこと（他のシェーダーはGLTFに正しく変換されない） |

> PBRテクスチャを使う場合、Principled BSDF の各ソケットに直接 Image Texture を接続してください。  
> ノードグループやカスタムシェーダーを挟むと、エクスポート時にマテリアルが失われます。

### 【階層1 MergedBackground】エクスポート手順

1. エリアに属するすべての静的オブジェクトを選択
2. **Ctrl+J** でJoin（ひとつのオブジェクトにまとめる）
3. マテリアルは **10スロット以内** に整理（同じ色のものはマテリアルを統一）
4. アニメーション OFF でエクスポート

> **目標:** 1GLBファイル・10DrawCall以内。ポリゴン数上限なし（LODは後工程）。

### 【階層2 Instanced】エクスポート手順

1. **1個だけ** 丁寧に作る（複数個は作らない）
2. オリジンを **足元 Y=0** に設定
3. アニメーション OFF でエクスポート

> 「どこに何個置くか」はエンジニアがデータで定義する。デザイナーは形だけ作ればよい。

### 【階層3 AnimLoop】エクスポート手順

before / after の見た目の差分を **モーフターゲット（シェイプキー）** で表現する。

| 項目 | 設定値 |
|------|--------|
| シェイプキー `before` | 変化前の形 |
| シェイプキー `after` | 変化後の形 |
| シェイプキーのエクスポート | **ON** |
| 名前 | 英語のみ（`before`, `after`, `shrink`, `fade` 等） |
| オリジン | 足元 Y=0 |

> モーフターゲットが不要な場合（色変化のみ等）はシェイプキーなしでOK。  
> エンジニアに「色のみ」「スケールのみ」「モーフあり」を必ず伝えること。

### 【階層4 Rigged】エクスポート手順

| 項目 | 設定値 |
|------|--------|
| ボーン | GLB内に含める |
| アニメーション | **ON**（使用するクリップ名を一覧でエンジニアに伝える） |
| シェイプキー（表情） | **ON**（顔がある場合） |
| シェイプキー名 | `eye_Smile`, `mouth_Open` 等（英語） |

#### モブNPC（頂点アニメーション）の扱い
人物モブを頂点アニメ（ボーンなしのモーフターゲット歩行）で作る場合：
- シェイプキーで歩行フレームを定義（`walk_00`〜`walk_07` など8フレーム分）
- エンジン側でモーフウェイトを時間でループさせる
- 階層は **Rigged** フォルダに置く（`mob_walk_v1.glb`）
- **複数の同一モブ** → 階層2 Instanced として扱いたい場合、エンジニアと要相談

### チェックリスト（書き出し前確認）
- [ ] オリジンが足元（Y=0）
- [ ] スケール適用済み（Apply Scale: Ctrl+A）
- [ ] 法線が正しい方向を向いている
- [ ] テクスチャがGLB内に埋め込まれている
- [ ] モーフターゲット名が英語・スペースなし

**カテゴリの選び方（4択）:**

| category | 対応階層 | 用途 |

階層1・2は登録不要。階層4（Rigged）は後述の専用定義ファイルに登録する。

**ファイル:** [src/data/worldObjects.ts](../src/data/worldObjects.ts)

makeObject({

  label: "カントリーマアム",
  changePattern: "A",
  eventSize: "large",
  position: [2.2, 1.1, -6],

**新しいWorldObjectを追加する場合**は `WORLD_OBJECTS` 配列の末尾に追記：

```typescript
makeObject({
  id: "my_new_object",
  checkpointId: 3,
  label: "表示ラベル",
  changePattern: "B",     // A=露骨(14秒ループ) / B=中間(22秒) / C=微妙(34秒)
  eventSize: "small",     // "large" | "small"
  position: [x, y, z],
  assetId: "my_asset_id", // AnimLoopカテゴリのassetIdのみ
}),
```

| 項目 | 仕様 |
|------|------|
| 形式 | PNG（透過あり）/ JPG（透過なし） |
| サイズ | 2のべき乗（512, 1024, 2048px） |
| 最大サイズ | 2048 × 2048px |
| カラースペース | sRGB（※Normal Mapのみ **Non-Color**、後述） |
| MergedBackground テクスチャ | アトラスにまとめること（1枚 2048×2048 推奨） |

### PBRマテリアル仕様

このゲームは Three.js の `MeshStandardMaterial` を使用しており、GLBに埋め込まれたPBRマップはそのまま有効です。  
フォトベース（フォトグラメトリ・写真投影）でアセットを作る場合は以下の仕様に従ってください。

#### 対応マップ一覧

| マップ | GLTFスロット | カラースペース | 備考 |
|--------|------------|--------------|------|
| Albedo (Base Color) | `baseColorTexture` | **sRGB** | 拡散色。ライティングの影響を受ける |
| ORM テクスチャ | `metallicRoughnessTexture` + `occlusionTexture` | **Non-Color** | R=AO / G=Roughness / B=Metalness の1枚にパック |
| Normal Map | `normalTexture` | **Non-Color** | OpenGL形式（Y軸が上、BlenderデフォルトのOpenGL設定でOK） |
| Emissive | `emissiveTexture` | **sRGB** | 自発光。看板・ディスプレイ等に使用 |

> **カラースペースの誤設定は最も多いミスです。** Normal MapとORMを誤って sRGB にすると  
> レンダリング結果が壊れます。Blender の Image Texture ノードで必ず **Non-Color** に設定してから書き出してください。

#### ORMテクスチャのパック方法（Blender）

フォトベースアセットのRoughnessは写真から抽出したグレースケールをそのまま使えます。

1. Compositor または Image Editor で3枚のグレースケール画像を合成：
   - **R チャンネル** → AO（Ambient Occlusion）マップ
   - **G チャンネル** → Roughness マップ
   - **B チャンネル** → Metalness マップ（非金属なら真っ黒 = 0.0 でOK）
2. PNG で書き出し（JPGは圧縮劣化でRoughnessが荒れる）
3. GLBエクスポート時に自動的に `metallicRoughnessTexture` / `occlusionTexture` に割り当てられる

> フォトベース素材は多くの場合 **Metalness = 0**（非金属）です。  
> Bチャンネルは真っ黒の1枚をそのまま使えばORMとして機能します。

#### Blenderエクスポート前チェックリスト（PBR追加分）

- [ ] Albedo の Image Texture ノードが **sRGB**
- [ ] Normal Map の Image Texture ノードが **Non-Color**
- [ ] ORM テクスチャの Image Texture ノードが **Non-Color**
- [ ] Normal Mapノードの **Strength** が適切（フォトグラメトリは 0.5〜0.8 推奨）
- [ ] Metalness が意図通り（非金属 = 0.0、金属 = 1.0）
- [ ] GLBエクスポートで **「Images > Format: JPEG / PNG」** を確認（埋め込み）

### DrawCall バジェット（目標）

| カテゴリ | 目標 DrawCall |
|----------|--------------|
| MergedBackground 1エリア | ≤ 5 |
| Instanced（種類数） | ≤ 10 |
| AnimLoop（ゲームオブジェクト） | 個数分（設計上やむなし） |
| Rigged（登場キャラ合計） | ≤ 20 |
| **1チェックポイント合計** | **≤ 100** |

### 3D座標系

| 軸 | 方向 |
|----|------|
| X | 左右（+が右） |
| Y | 上下（+が上） |
| Z | 前後（−がカメラ方向、奥へ行くほど小さい値） |

現在のストリートの大きさ：約 **X: -10〜10、Z: 0〜-25**

### 回転の単位

| 度数 | ラジアン |
|------|----------|
| 90° | `Math.PI / 2` ≈ 1.5708 |
| 180° | `Math.PI` ≈ 3.1416 |
| 270° | `Math.PI * 1.5` ≈ 4.7124 |

### 状態ごとのマテリアル色（AnimLoopのみ）

| 状態 | 発光色 | 意味 |
|------|--------|------|
| REAL | なし | 通常 |
| RECORDED | 青（`#2a4a6a`） | 徹が記録済み |
| RESISTANT | 金（`#c8a85a`） | 強い意志で改竄耐性あり |
| OVERWRITTEN | なし（after固定） | すでに改竄されている |

## 13. よくあるトラブル

### モデルが表示されない
- `assetTemplates.ts` の `modelPath` が正しいか確認
- ファイルが `public/` 以下にあるか確認
- ブラウザのコンソールで `404` エラーが出ていないか確認

### モデルの位置がズレる
- Blenderでエクスポート前にオリジンを足元（Y=0）に設定する

### モーフターゲットが動かない
- GLBエクスポート時にシェイプキーのエクスポートが有効になっているか確認
- 名前にスペースや日本語が含まれていないか確認

### エディタが開かない
- 開発サーバー（`npm run dev`）が起動しているか確認
- 本番ビルドではエディタは含まれない
- `F2` キーを押してもUIが出ない場合はコンソールのエラーを確認

### PBRマテリアルが正しく見えない（ノーマル・ラフネスが効いていない）
- Blenderのマテリアルが **Principled BSDF** ベースになっているか確認
- Normal Map / ORM テクスチャの Image Texture ノードのカラースペースが **Non-Color** になっているか確認（sRGBのままだと色化けする）
- `normalTexture` の strength（影響度）が大きすぎないか確認（フォトグラメトリは 0.5〜0.8 推奨）

### フォトグラメトリのテクスチャが暗すぎる / 明るすぎる
- Albedo テクスチャにライティング情報（ベイクされたAO等）が含まれている場合、ゲーム内のライトと二重になる
- フォトグラメトリからAlbedoを書き出す際は **ライティングを除去（デライティング）** してから使うことを推奨
- 応急処置として `emissive` で底上げするか、`ambientLight` の強度をエンジニアと相談

### カテゴリが `Furniture` / `Background` / `Character` になっている（旧仕様）
- 新仕様では `Instanced` / `AnimLoop` / `Rigged` に移行する
- エンジニアに相談して `assetTemplates.ts` の型定義ごと更新する
