# NPC ウェイポイント命名ガイドライン
**対象: 3D デザイナー**  
プロジェクト: 『前からこうでした』

---

## 0. 概要

NPC キャラクターの移動経路は **Blender 上に配置した Empty（空オブジェクト）** で定義します。  
エンジン（Three.js）はこの Empty の座標を読み取り、CatmullRomCurve3（スムーズ補間曲線）として NPC を歩かせます。

```
Blender上の Empty ──→ GLB エクスポート ──→ Three.js が座標を取得
  wp_passerby_01_001        street_act1.glb      curve.getPoint(t)
  wp_passerby_01_002                             で NPC を進める
  wp_passerby_01_003
```

> **デザイナーがやること:** Empty を置いて正しい名前をつけるだけ。  
> **エンジニアがやること:** Three.js 側でその座標を読み込んで NPC を動かす処理を書く。

---

## 1. 命名規則

### 基本フォーマット

```
wp_{character_key}_{連番3桁}
```

| 部分 | 意味 | 例 |
|------|------|-----|
| `wp` | Waypoint の接頭辞（固定） | `wp` |
| `{character_key}` | NPC の識別子（後述の対応表を参照） | `passerby_01` |
| `_{連番3桁}` | 経路の順番（001 から始まる、ゼロ埋め） | `_001`, `_002` |

### 具体例

| Empty 名 | 意味 |
|----------|------|
| `wp_passerby_01_001` | 通行人①の経路ポイント 1番目 |
| `wp_passerby_01_002` | 通行人①の経路ポイント 2番目 |
| `wp_passerby_01_003` | 通行人①の経路ポイント 3番目 |
| `wp_shopkeeper_01_001` | コンビニ店員の経路ポイント 1番目 |
| `wp_shopkeeper_01_002` | コンビニ店員の経路ポイント 2番目 |

### NPC ID と character_key の対応表

| ゲームコード上の NPC ID | Blender で使う character_key |
|------------------------|------------------------------|
| `npc_passerby_01` | `passerby_01` |
| `npc_shopkeeper_01` | `shopkeeper_01` |

> `npc_` プレフィックスを除いた部分がそのまま `character_key` になります。  
> 新しい NPC を追加するときはエンジニアに NPC ID を確認してから作業してください。

## 2. 経路の種類と番号の振り方

### 周回ルート（ぐるっと一周する）

番号順に歩いて最後のポイントから最初のポイントへ自動的に戻ります。

```
001 → 002 → 003 → 004 → （001へ戻る）
```

通行人のように街をぐるぐる歩かせたい場合はこちら。  
最後のポイントは**最初と同じ場所にしない**（エンジン側で自動ループするため二重になる）。

### 往復ルート（折り返し）

コードで `loop: false` を指定した場合、端から端まで歩いて折り返します。

```
001 → 002 → 003 → 002 → 001 → ...
```

コンビニ店員が店先を往復するような場合。  
往復にするかどうかはエンジニアに伝えて、コード側で設定してもらいます。

## 3. Blender での作業手順

### 3-1. Empty を配置する

1. **`Shift+A` → `Empty` → `Plain Axes`** を選択
2. キャラが歩くルート上に、間隔をある程度均等に置く（目安: 2〜5m 間隔）
3. Y 座標（高さ）は **0** に揃える（地面の高さ）

> ポイントの間隔が広すぎると曲線が直線的になります。  
> カーブにしたい箇所は密に置いてください。

### 3-2. 名前をつける

アウトライナーで Empty を選択 → **ダブルクリック** で名前を編集

```
wp_passerby_01_001
```

**よくあるミス:**
- スペース・大文字・日本語を使わない
- アンダースコアの数や位置をミスしない（`wp_` + `character_key` + `_` + `001`）
- 連番は必ず **3桁ゼロ埋め**（`1` ではなく `001`）

### 3-3. Collection に格納する

アウトライナーで以下の構造を作ってください：

```
Scene Collection
├── WaypointPaths/              ← ウェイポイント専用 Collection（新規作成）
│   ├── wp_passerby_01/         ← NPC ごとにサブ Collection を作る
│   │   ├── wp_passerby_01_001
│   │   ├── wp_passerby_01_002
│   │   └── wp_passerby_01_003
│   └── wp_shopkeeper_01/
│       ├── wp_shopkeeper_01_001
│       └── wp_shopkeeper_01_002
└── （その他の街オブジェクト）
```

> **なぜ Collection を分けるか:** GLB エクスポート時に「WaypointPaths のみ表示を除外」しやすくするためです。  
> ゲーム本番には不要なので、レンダリング時は非表示にします（エクスポートは含めてください）。

## 4. エクスポート設定

ウェイポイント Empty は **ストリートの背景 GLB と同じファイルに含めて** エクスポートします。

| 項目 | 設定値 |
|------|--------|
| フォーマット | GLB |
| エクスポート対象 | 街背景メッシュ ＋ WaypointPaths Collection の Empty |
| Y-up 変換 | ON |
| アニメーション | OFF |
| **Data > Include > Custom Properties** | **ON**（後述の補足情報を含める場合） |

> Empty はメッシュを持たないため GLB サイズにほとんど影響しません。  
> 通常の背景エクスポートと同じ手順で一緒に書き出してください。

---

## 5. Custom Properties（任意・応用）

Blender の **Object Properties > Custom Properties** を使うと、  
移動速度などのパラメータを Empty に付加して GLB 経由でエンジンに渡せます。

### 設定方法

Empty を選択 → **Object Properties（オレンジのアイコン）**  
→ 下部の **Custom Properties** パネル → **「+」で追加**

| プロパティ名 | 型 | 値の例 | 意味 |
|-------------|-----|--------|------|
| `speed` | Float | `1.5` | このポイントを通過する速度係数（1.0が標準） |
| `pause` | Float | `2.0` | このポイントで何秒停止するか（0=通過） |
| `loop` | Int | `1` / `0` | 1=周回ルート、0=往復ルート（全ポイント共通で最初のポイントに設定） |

> **基本的には不要です。** 特別な演出（特定の場所で立ち止まるなど）が必要なときだけ  
> エンジニアと相談のうえ設定してください。

---

## 6. ビューポート表示について

Empty が多くなると作業しにくくなるので、以下の工夫を推奨します。

- **Empty のサイズ:** Object Data Properties → Size を `0.3`〜`0.5` に小さくする
- **表示色:** Empty の色を WaypointPaths Collection の Collection Color で統一する（アウトライナー右クリック）
- **通し番号の確認:** アウトライナーでソートして順番が飛んでいないかチェックする

---

## 7. チェックリスト（エクスポート前）

- [ ] Empty の名前が `wp_{character_key}_{3桁}` の形式になっている
- [ ] 連番が `001` から始まり、途中が飛んでいない
- [ ] スペース・大文字・日本語が含まれていない
- [ ] すべての Empty が `WaypointPaths` Collection に入っている
- [ ] Y 座標（高さ）が 0 に揃っている
- [ ] GLB エクスポート時に WaypointPaths Collection が含まれている
- [ ] エクスポートした GLB をエンジニアに渡す際に「新規キャラ追加か / 既存ルート変更か」を伝える

## 8. Three.js 側の仕組み（参考）

デザイナーは作業不要ですが、仕組みを把握しておくと確認作業がしやすくなります。

```
GLB 読み込み
  ↓
scene を traverse して名前が wp_ で始まるノードを収集
  ↓
character_key ごとにグループ化 → 番号順にソート
  ↓
THREE.CatmullRomCurve3 を生成
  ↓
useFrame の中で t（0〜1）を進めて NPC の位置を更新
```

- 連番がひとつでも抜けると、その NPC のルートが正しく読み込まれません
- 名前の形式が少しでも違うと Three.js 側で検出されません（スペース・大文字に注意）
