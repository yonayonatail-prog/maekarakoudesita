## 1. システム設計（状態管理・データ構造）

### 1-1. 世界の状態モデル

各オブジェクトは以下の4状態を持つ。

```typescript
type ObjectState =
  | "REAL"        // 世界の現在の真実（プレイヤーに見えている）
```

### 2-3. コリジョン設計

Three.jsにはネイティブの物理エンジンがないため、以下の方針で実装する。

**採用方式**: `Raycaster`ベースのコリジョン検出

```typescript
// 歩行コリジョン（壁・床）
// プレイヤーの足元と前方にRayを飛ばし、衝突判定する
const collisionRaycaster = new THREE.Raycaster();

// 壁コリジョン用メッシュ（見えない透明メッシュ）
// 建物・看板・フェンス等に配置
const collisionMeshes: THREE.Mesh[] = [];

// 毎フレームの判定
function checkCollision(direction: THREE.Vector3): boolean {
  collisionRaycaster.set(playerPosition, direction);
  const intersects = collisionRaycaster.intersectObjects(collisionMeshes);
  return intersects.length > 0 && intersects[0].distance < PLAYER_RADIUS;
}
```

**コリジョンの種類**:

| 種類 | 対象 | 処理 |
|------|------|------|
| 壁コリジョン | 建物・看板・フェンス | 移動をブロック |
| 床コリジョン | 地面 | Y軸を固定（重力代替） |
| トリガーコリジョン | 特定のオブジェクト付近 | スコープ起動を促すUI表示 |
| 境界コリジョン | マップ端 | 不可視の壁で封鎖 |

**注意**: 複雑な物理演算が必要な場合は`cannon-es`または`rapier`（WASM）の導入を検討する。ただし初期実装はRaycasterで十分。

## 3. 撮影メカニクス（animloop・両端撮影）

### 3-1. animloopの仕組み

チェックポイントでは「変化前」と「変化後」がループアニメーションで交互に流れる。

```typescript
interface AnimloopObject {
  objectId: string;
  beforeState: THREE.Object3D;   // 変化前（例：長いスカート）
  afterState: THREE.Object3D;    // 変化後（例：短いスカート）
  loopDuration: number;          // 1ループの秒数
  changePattern: "A" | "B" | "C";
}

// changePatternによるループ速度
const LOOP_SPEEDS = {
  A: 3.0,   // 第1幕チュートリアル：ゆっくり・明確
  B: 1.5,   // 中盤：やや速い・注意が必要
  C: 0.8,   // 終盤：一瞬・スコープ必須
};
```

**オブジェクト別難易度設定例**:

| オブジェクト | パターン | ループ速度 | 備考 |
|------------|---------|----------|------|
| 歯科の看板（院長の顔） | C | 0.8s | 終盤・スコープ必須 |
| JKのスカート丈 | B | 1.5s | 標準難易度 |
| コンビニの棚 | B | 2.0s | やや余裕あり |
| カントリーマアム | A→C | 幕に応じて変化 | 第1幕のみA |
| 通行人の数 | C | 0.5s | 上級者向け |

### 3-2. 撮影メカニクスの詳細

**記録の条件**: 「変化前」と「変化後」の両端を撮影して初めてログに記録される。

```typescript
type CaptureResult =
  | "SUCCESS"          // 両端撮影完了→ログ記録
  | "PARTIAL"          // 片方のみ→次のチェックポイントまで保持
  | "MISS"             // 変化なしのタイミングで撮影→何も起きない
  | "OVERWRITTEN"      // すでに改変済みのオブジェクトを撮影

function handleCapture(objectId: string, currentPhase: "before" | "after"): CaptureResult {
  const obj = getWorldObject(objectId);
  if (currentPhase === "before") {
    obj.beforeCaptured = true;
  } else {
    obj.afterCaptured = true;
  }
  if (obj.beforeCaptured && obj.afterCaptured) {
    recordAnomalyLog(obj);
    return "SUCCESS";
  }
  return "PARTIAL";
}
```

**スロット制限**: 廃止。時間制限（5〜8分）のみでペナルティを設計する。

**外れ撮影**: 変化のないタイミングでタップしてもペナルティなし・ログに記録されない。

### 3-3. シャッターUI

- タップ（スマホ）またはクリック（PC）で撮影
- シャッター音はSEとして再生
- 撮影成功（SUCCESSとPARTIAL）は異なるSE・エフェクトで区別
- 時間制限の残り時間はスマホUIのバッテリー風インジケーターで表現

### 3-4. difF対象の定義：「高速変化はdifFではない」

**原則**: difF（シュリンクフレーション撮影メカニクス）は、**静止〜緩慢な変化**にのみ成立する。

| 変化の種類 | difF対象か | 例 |
|-----------|-----------|-----|
| 静止・固定 | ✅ 対象 | 看板の文字、商品サイズ |
| 緩慢な変化（A/B/Cパターン） | ✅ 対象 | JKのスカート丈、カントリーマアム |
| **高速連続変化** | ❌ **対象外** | **桜並木の365日サイクル、高速世界の演出的変化** |

**根拠**: 「比較・測定できないほど速いもの」は、difFという認知メカニクスの本質と相容れない。高速変化は「時間の流れが速い場所の演出」であり、違和感ログの撮影対象にはならない。

- 高速変化オブジェクトにカメラを向けても撮影UIは表示されない
- プレイヤーはその挙動から「ここは時が速い」と直感的に読み取る（UI説明なし）

## 4. ログシステム（記録・改変・耐性）

### 4-1. 違和感ログの記録

撮影成功（両端撮影完了）でログが作成される。

```typescript
function recordAnomalyLog(obj: WorldObject): void {
  const log: AnomalyLog = {
    id: generateId(),
    objectId: obj.id,
    checkpointId: currentCheckpoint,
    timestamp: `あの事件から${getDaysSinceIncident()}日目`,
    beforeCapture: captureScreenshot("before"),
    afterCapture: captureScreenshot("after"),
    isResistant: checkResistance(obj),
    isOverwritten: false,
    note: generateAutoNote(obj),   // ノベルパートで自動生成されるメモ
  };
  playerState.anomalyLog.push(log);
  checkBranchUnlock(obj.branchFlag);
}
```

### 4-2. わらしべ式ブランチ

記録した違和感がブランチフラグを解放し、次のイベントが出現する。

```typescript
interface Branch {
  flagId: string;              // このブランチのID
  triggerObjectId: string;     // このフラグを立てるオブジェクト
  unlocksObjectIds: string[];  // 解放される次のオブジェクト群
  endingFlagContribution: EndingFlag; // エンディングへの貢献
}

// 例：カントリーマアムを記録 → 店員の名札イベント出現
const BRANCH_COUNTRY_MAAM: Branch = {
  flagId: "branch_country_maam_001",
  triggerObjectId: "country_maam_size",
  unlocksObjectIds: ["staff_nameplate_001"],
  endingContribution: "NORMAL_OR_TRUE",
};
```

### 4-3. 改変耐性ログの判定

「強い想いを込めた記録」だけが改変に耐える。判定条件は以下の複合スコア。

```typescript
function checkResistance(obj: WorldObject): boolean {
  let resistanceScore = 0;

  // 条件1：七海に直接関連するオブジェクト（+50点）
  if (obj.relatedToNanami) resistanceScore += 50;

  // 条件2：TRUEエンドに必要なブランチを通ったか（+30点）
  if (isOnTruePath(obj)) resistanceScore += 30;

  // 条件3：タイムリープ後に再記録したか（+20点）
  if (isRerecordedAfterTimeleap(obj)) resistanceScore += 20;

  // 条件4：複数チェックポイントにわたって継続観察したか（+20点）
  if (isObservedMultipleCheckpoints(obj)) resistanceScore += 20;

  return resistanceScore >= 50;
}
```

### 4-4. ログの改変演出

記録しなかった違和感は次のチェックポイント移動時に上書きされる。

```typescript
function applyWorldOverwrite(checkpoint: number): void {
  for (const obj of getCheckpointObjects(checkpoint)) {
    if (!obj.isRecorded && !obj.isResistant) {
      obj.state = "OVERWRITTEN";
      // UIにも反映：過去のログ写真がぼやける・圧縮される
      degradeLogCaptures(obj.id);
    }
  }
}
```

**改変される対象の範囲**:

| 対象 | 改変の内容 |
|------|----------|
| 過去のログ写真 | ぼやける・AI補正がかかる・圧縮される |
| メモ | 文字が薄くなる・一部が消える |
| UI上のタイムスタンプ | 日付がずれる |
| スタート画面 | 毎回起動するたびにUIが少しずつ小さくなる（隠し要素） |

**改変されない対象**:

- 改変耐性ログ（isResistant: true）
- セーブデータ本体（演出のみ・実害なし）

## 5. タイムリープシステム（認知削れ）

### 5-1. タイムリープの仕組み

カントリーマアムの賞味期限間際の個体を食べることで認知が1年前に巻き戻る。

```typescript
interface TimeleapSystem {
  isAvailable: boolean;          // タイムリープ可能か
  cognitionCost: number;         // 1回あたりの認知削れ量
  totalCount: number;            // 累計タイムリープ回数
}

function executeTimeleap(): TimeleapResult {
  if (playerState.cognitionLevel <= 0) {
    return "PARANOIA_TRIGGER";   // PARANOIAエンドへ
  }
  playerState.timeleapCount++;
  playerState.cognitionLevel -= calculateCognitionCost();
  rewindToOneYearAgo();
  return "SUCCESS";
}

// 認知削れ量は回数に応じて増加（序盤は安全、中盤以降は危険）
function calculateCognitionCost(): number {
  const base = 5;
  const multiplier = 1 + (playerState.timeleapCount * 0.1);
  return Math.min(base * multiplier, 25); // 最大25まで
}
```

### 5-2. 認知レベルの影響

```
cognitionLevel: 100〜70  → 正常。世界が正確に見える
cognitionLevel: 70〜40   → 視界に軽いノイズ・歪み
cognitionLevel: 40〜20   → NPCの顔が歪んで見える
cognitionLevel: 20〜1    → 世界全体が不安定に揺れる
cognitionLevel: 0        → PARANOIAエンドへ強制遷移
```

### 5-3. 七海との再会

タイムリープで1年前に戻ると生きている七海に会える。

- 再会のノベルパートを厚く描く（喜びを最大化）
- 直後にチェックポイント探索が始まり、また七海を失う流れになる
- 「何度でも会えて、何度でも失う」を繰り返すことで喪失の重みを積み上げる

## 6. エンディング分岐条件

### 6-1. 分岐の仕組み（パターンZ：ハイブリッド）

累積フラグが「最終選択肢の数」を決定し、プレイヤーが能動的に選ぶ。

```typescript
type EndingFlag =
  | "TRUE_PATH"       // TRUEエンドへの必須フラグ
  | "NORMAL_OR_TRUE"  // NORMALかTRUEへの貢献
  | "BAD_PATH"        // BADへの傾き
  | "PARANOIA_PATH"   // PARANOIAへの傾き
  | "PATROL_PATH"     // パトカーエンドへの傾き

function calculateFinalChoices(flags: EndingFlag[]): Ending[] {
  const trueCount = flags.filter(f => f === "TRUE_PATH").length;
  const choices: Ending[] = ["BAD", "NORMAL"]; // 最低限の選択肢

  if (trueCount >= TRUE_THRESHOLD) choices.push("TRUE");
  if (flags.includes("PATROL_PATH")) choices.push("PATROL");

  return choices;
}
```

### 6-2. 各エンディングの条件

| エンディング | 条件 | 体験 |
|------------|------|------|
| **TRUE** | TRUE_PATHフラグ最大数 + 自分でTRUEを選択 | 犬歯照合→水城逮捕。でも15年も七海も戻らない |
| **PARANOIA** | cognitionLevel 0到達 | 鏡の自分に「……誰？」 |
| **BAD** | 記録不足・BAD_PATH多数 | 世界へ完全同化。ニュースの犯人（自分）を他人事のように見る |
| **NORMAL** | 中程度の記録・証拠不十分 | 誰も信じない。数年後また別の誰かが狙われる |
| **パトカー** | 力ずく行動・白昼夢誤認 | 社会システムに排除される。窓から水城の顔が徹の顔に |

### 6-3. TRUEエンドが「選びにくい」設計

TRUEを選択した瞬間、以下のノベルパートが入る。

> 「もう二度と、生きている七海には会えない。」
> 「それでも、選ぶか？」

タイムリープ（七海との再会）を永遠に諦める選択だからこそ、プレイヤーが躊躇する。これ自体がゲーム体験。

## 9. ノベルパートシステム（セーブ・バックログ等）

### 9-1. パートの切り替え

```
3Dフィールドパート（チェックポイント探索）
      ↓ 定期検診通知 or 帰宅アクション
ノベルパート（テキスト・立ち絵・白昼夢演出）
      ↓ 就寝（1年経過）
次のチェックポイントへ
```

### 9-2. ノベルパートの機能

| 機能 | 仕様 |
|------|------|
| **バックログ** | 過去のセリフを遡れる。スクロール式。改変済みのセリフはグレーアウト |
| **任意セーブ** | ノベルパート中のみ可能。最大9スロット |
| **オートセーブ** | チェックポイント到達時に自動実行（3Dパートは任意セーブ不可） |
| **オートモード** | セリフが自動送り。速度は設定で調整可能 |
| **スキップ** | 既読テキストのみ高速スキップ可能。未読テキストはスキップ不可 |
| **テキスト速度** | 設定で3段階（遅・普通・速）調整 |

### 9-3. セーブデータの改変演出と実害の分離

```typescript
// 演出：セーブデータが書き換えられたように見せる
function showFakeSaveCorruption(): void {
  // UIのみ改変。実データは一切変更しない
  renderCorruptedSaveUI();
  playCorruptionSound();
}

// 実データは別の名前空間で完全に保護
const REAL_SAVE_DATA_KEY = "__real_save_protected__";
function saveRealData(data: PlayerState): void {
  localStorage.setItem(REAL_SAVE_DATA_KEY, JSON.stringify(data));
}
```

### 9-4. 白昼夢演出

定期検診の麻酔椅子でのノベルパート。幕が進むごとに現実と見分けがつかなくなる。

| 検診回 | 白昼夢の質感 | 実装 |
|--------|------------|------|
| 1〜2回（第1幕） | 白いフラッシュのみ | 単色フラッシュ + SEのみ |
| 3〜7回（第2幕） | 輪郭のぼやけた幻視 | ガウスブラーをかけたノベル画像 |
| 8〜11回（第3幕） | 音・色が混じる | 歪みシェーダー + 異常SEレイヤー |
| 12〜15回（第4幕） | 現実と見分けがつかない | 通常ノベルと同一品質。覚めた後も「夢だった」と言い切れない |

## 10. サウンド設計仕様

### 10-1. BGMのレイヤー構造

BGMは複数の楽器レイヤーで構成され、幕が進むにつれて楽器が減っていく。

```typescript
interface BGMLayer {
  instrument: string;
  audioBuffer: AudioBuffer;
  volume: number;
  activeUntilCheckpoint: number; // このCPを過ぎると消える
}

const BGM_LAYERS: BGMLayer[] = [
  { instrument: "strings",  activeUntilCheckpoint: 14 }, // 最後まで残る
  { instrument: "piano",    activeUntilCheckpoint: 10 },
  { instrument: "woodwind", activeUntilCheckpoint: 6 },
  { instrument: "brass",    activeUntilCheckpoint: 3 },
  { instrument: "percussion", activeUntilCheckpoint: 2 },
];
```

### 10-2. SE一覧

| SE名 | タイミング | 備考 |
|------|----------|------|
| `shutter_success` | 両端撮影成功 | 高めの心地よい音 |
| `shutter_partial` | 片方のみ撮影 | やや不完全な音 |
| `shutter_miss` | 外れ撮影 | ほぼ無音 or ごく小さな音 |
| `overwrite_start` | CP移動時の改変開始 | ノイズ・歪み音 |
| `log_resistant` | 改変耐性ログ確定 | 温かみのある音 |
| `timeleap_activate` | タイムリープ発動 | 逆再生音 |
| `cognition_warning` | 認知レベル低下警告 | 不安を煽る持続音 |
| `dental_notification` | 定期検診通知 | スマホ通知音（不穏にアレンジ） |
| `anesthesia` | 麻酔椅子着席 | 笑気ガス音 → 意識が溶ける音 |

### 10-3. 無音の使い方

- 改変後の世界は一つの楽器が消えるだけでなく、環境音（人の声・車の音）も少しずつ減る
- 最終幕では完全に静寂に近い状態になり、徹の足音と心拍音のみが残る
- TRUEエンドのクライマックスは「完全な無音」→「片方だけのマグカップを置く音」で締める

### 13-3. ローカライズ方針

- **UIテキスト**: 言語パックJSONで完全対応。`t("ui.start_button")` のような関数で呼び出す。
- **シナリオテキスト**: 日本語版を正とする。英語版は直訳禁止・意訳・ニュアンス優先。
- **タイトル「前からこうでしたよ」**: 英語版では `"It's Always Been This Way."` の英題を使用。直訳の追加説明は不要。
